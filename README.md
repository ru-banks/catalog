# Каталог банков Unibank

[English](README_EN.md)

Подписанный каталог и зашифрованные спецификации банков для клиента Unibank.
Приложение скачивает каталог и спецификации отсюда. Исходники опубликованных
банков и приватные ключи лежат в другом репозитории.

## Что в репозитории

```
index.json            файл, который подписан
index.json.sig        подпись к нему в base64url
specs/<id>-<ver>.ubx  зашифрованная спецификация банка
logos/<id>.<ext>      логотип банка, если он есть
docs/                 документация для разработчиков спецификаций
```

## Поддерживаемые банки

Таблица соответствует каталогу на 27.11.2026; точные версии и состав
возможностей — в [`index.json`](index.json). Все банки в статусе **beta**:
приложение читает собственные счета, карты и операции, но не переводит деньги.

`✓` — возможность есть в опубликованной спецификации, `—` — нет.

| Банк | Балансы | Карты | История операций | Кэшбэк и выбор категорий | История кэшбэка | Ограничения |
|---|:---:|:---:|:---:|:---:|:---:|---|
| **Т-Банк** | ✓ | ✓ | ✓ | ✓ | — | Живой вход ещё не проверялся — только ответы, записанные ранее, и тестовый сценарий. Переводы по СБП отключены. |
| **ВТБ** | ✓ | ✓ | ✓ | ✓ | — | Вход по СМС. Банк может не принять автоматическое продление — тогда нужен код доступа или повторный вход. Категории кэшбэка зависят от месяца и продукта. |
| **Альфа-Банк** | ✓ | ✓ | ✓ | ✓ | ✓ | Вход требует человека: телефон, секретный код и СМС; антифрод может попросить подтвердить личность. Выбор категорий «Апельсина» живой записью не проверялся. |
| **МТС Деньги** | ✓ | ✓ | ✓ | ✓ | — | Поддерживается только банк «МТС Деньги». МТС Банк — отдельный банк, его счета и карты, включая карту «МТС Деньги», не читаются. только читает данные. Это следующий шаг, а не скрытая возможность.

## Как добавить банк

Спецификация банка описывает, как войти в банк, какие запросы отправлять, как
разобрать ответ и какие ответы считать ошибками. Это JSON-файл. Кода банка в
приложении нет, спецификацию исполняет движок.

Сделать её может любой:

1. Откройте issue «Новый банк» и напишите, что уже получилось.
2. Соберите спецификацию по [docs/README.md](docs/README.md). С ИИ-агентом
   это быстрее: он скачивает APK, разбирает протокол и пишет черновик. Порядок
   и готовый промпт — в [docs/ai-agent.md](docs/ai-agent.md).
3. Пришлите pull request с незашифрованной спецификацией и заметками о
   протоколе.
4. После ревью мы публикуем банк в каталоге.

Документация:

- [docs/ai-agent.md](docs/ai-agent.md): как собрать спецификацию с ИИ-агентом
  и готовый промпт;
- [docs/process.md](docs/process.md): как проходит работа от issue до
  публикации;
- [docs/spec-v1.md](docs/spec-v1.md): язык спецификаций;
- [docs/capabilities.md](docs/capabilities.md): что обязательно, а что
  необязательно;
- [docs/checklist.md](docs/checklist.md): какие доказательства приложить к
  pull request;
- [docs/examples/bank1.spec.json](docs/examples/bank1.spec.json): пример
  спецификации демо-банка.

Issue и pull request видны всем. Не кладите туда токены, cookie, номера счетов,
данные карт и персональные данные.

## Как приложение читает каталог

1. Скачивает `index.json` и проверяет подпись ключом, который вшит в
   приложение.
2. Скачивает `.ubx` нужного банка и сверяет хэш и размер с каталогом.
3. Расшифровывает спецификацию и проверяет её по схеме.

Пользовательских данных в каталоге нет. Каталог собирает
`tools/spec/publish.ts` в репозитории клиента. Артефакты не меняются: откат
делается новым каталогом поверх.

## Зачем спецификации зашифрованы

Спецификация — это готовая инструкция: какие запросы отправить, какие заголовки
и подписи нужны, как разобрать ответ. В открытом виде она полезна не только
разработчикам, поэтому в каталоге лежит зашифрованный `.ubx`, а не исходный
JSON.

- **Магазины приложений.** Среди поддерживаемых банков есть банки под
  санкциями. Публичный репозиторий с готовыми рецептами к их внутренним API —
  лишний материал для ревью Apple и Google. Шифрование не скрывает сам факт
  поддержки банка, но убирает готовую инструкцию из поиска и форков.
- **Сами банки.** Банки меняют внутренние API и усиливают антифрод. Когда
  спецификация лежит открытым текстом, её проще найти, сопоставить с трафиком и
  закрыть конкретные ручки. Зашифрованный артефакт повышает цену такого разбора
  и даёт время выпустить обновление через каталог, а не через релиз приложения.
- **Поиск и форки.** `.ubx` не индексируется поисковиками и не разносится по
  форкам как исходник.

Это не гарантия одобрения в App Store или Google Play: политика магазинов к
приложениям, которые работают с внутренними API банков, остаётся серой зоной.
Шифрование лишь снижает риск, что готовый рецепт станет публичным аргументом
против приложения.

Честная оговорка: **это обфускация, а не секретность.** Ключ расшифровки
поставляется вместе с клиентом, поэтому целеустремлённый человек всё равно
достанет спецификацию. Целостность обеспечивает не шифрование, а подпись
`index.json` и хэши артефактов: приложение не примет подменённый каталог.

## Уведомление

Названия банков и их протоколы принадлежат владельцам. Каталог не претендует
на официальную поддержку банков и не связан с ними. Пользуйтесь им только со
своими счетами и на свой риск.
