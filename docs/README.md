# Разработка спецификаций банков

Unibank показывает счета и операции нескольких банков в одном приложении.
Банк для приложения — это **спецификация**: JSON-документ, который описывает
вход, запросы, поля и маппинг в общий домен. Кода банка в приложении нет.
Движок исполняет спецификацию, поэтому починить банк можно обновлением
каталога, без релиза приложения.

Этот репозиторий — точка распространения: подписанный `index.json` и
зашифрованные артефакты спецификаций. Исходники опубликованных банков и ключи
лежат вне репозитория. Здесь только пример демо-банка.

**Спецификацию может разработать любой.** Готовую спецификацию присылают в
issue или PR незашифрованной; после ревью сопровождающий включает банк в
каталог.

## Как это выглядит

```
issue «Новый банк» → вы разбираете банк и пишете спецификацию →
PR со спецификацией и bank.md → ревью и правки → публикация в каталоге →
PR закрывается
```

Подробно — в [`process.md`](process.md). Если хотите поручить черновую работу
ИИ-агенту, начните с [`ai-agent.md`](ai-agent.md): там порядок действий, откуда
взять APK и готовый промпт.

## Что нужно, чтобы начать

- Умение читать HTTP-трафик и JSON.
- Свой аккаунт в банке: вход подтверждаете вы, чужие данные не нужны.
- Понимание, что внутренние API банка неофициальные и могут меняться.

Доступ к движку, ключам или приватному репозиторию не нужен. Спецификация —
это данные; синтаксис проверяет сопровождающий при ревью.

## Обязательный минимум

Банк принимается, если работают:

1. вход и продление сессии;
2. продукты с балансами;
3. история операций.

Карты обязательны, если банк их выпускает. Кэшбэк, переводы и прочее
необязательны. Полная таблица — в [`capabilities.md`](capabilities.md).

## Публичность и секреты

Issue и PR публичные. Незашифрованная спецификация останется в истории GitHub
и в форках, даже если PR не смержат: шифрование опубликованного артефакта
защищает каталог, но не скрывает то, что вы сами опубликовали.

Поэтому в спецификацию, `bank.md`, issue и PR не попадают:

- токены, cookie, пароли, ключи;
- реальные номера счетов и карт (PAN);
- ФИО, телефоны, адреса;
- скриншоты с этими данными.

Примеры ответов обезличиваются: структура сохраняется, значения заменяются
заглушками той же формы.

## Чего спецификация не умеет

- JavaScript, `eval`, инъекции в WebView.
- Хосты вне объявленного списка, `http://`.
- Операции с деньгами: переводы, платежи, блокировка карт. Выбор категорий
  кэшбэка — единственная запись, которую поддерживает язык.
- Разбор вёрстки и текста интерфейса вместо API.

Если для банка нужен новый примитив, это не повод городить обход. Напишите в
issue: примитив добавят в движок.
