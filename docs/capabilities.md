# Что обязательно, а что нет

Минимум для приёма в каталог: **вход в банк, продукты с балансами и история
операций**. Остальное зависит от того, что умеет банк.

Три уровня:

- **P0 — обязательно.** Без этого спецификация не проходит ревью.
- **P1 — обязательно, если банк это умеет.** Если не умеет, в `bank.md`
  пишется `[-]` с доказательством: нет экрана, нет эндпоинта, банк отвечает
  пустым списком. Молча пропускать нельзя.
- **P2 — необязательно.** Время на это не тратим; отсутствие не считается
  багом.

## P0: обязательный набор

### 1. Авторизация

- Полный вход на живом аккаунте: все способы, которые вы заявляете, пройдены
  вручную.
- Результат входа сохранён в `$secret.session` (токены, cookie-строка, id
  устройства — что нужно банку).
- Шаги, требующие человека (СМС, пуш, PIN, капча), описаны `emit`-шагами, а не
  скрыты.
- `restartOn` заполнен, если повторный ввод телефона должен начинать вход
  заново.

### 2. Продление сессии без человека

- `refresh` продлевает сессию без повторного входа (refresh token, silent SSO,
  cookie-ротация — что есть у банка).
- Если банк не продлевает сессию вообще, это допустимое исключение. Его нужно
  доказать и описать: сессия живёт N часов, дальше нужен вход. `check` в этом
  случае возвращает `expired`, приложение показывает «нужен вход».

### 3. Проверка живости сессии

- `check` — дешёвый запрос, который не тянет счета и историю.
- Различаются «сессия истекла», «нет прав» и «банк недоступен».

### 4. Продукты и балансы

- `read.accounts` — все продукты, которые видит человек в приложении банка:
  текущие, накопительные, вклады, кредиты, кредитные карты.
- Суммы совпадают с приложением банка на том же аккаунте в тот же момент.
- Валютные счета не складываются в рубли и не теряются.
- Закрытые продукты не выдаются как активные.

Обязательные поля счёта:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | string | Стабильный id; по нему связываются карты и операции. |
| `name` | string | Название как в приложении банка. |
| `kind` | `current` / `savings` / `deposit` / `credit` / `loan` / `unknown` | Тип продукта. |
| `currency` | ISO-4217 | `RUB`, `USD`, `EUR`, … |
| `balance` | `{ minor, currency }` | Баланс в минорных единицах (копейках). |

Необязательные, но нужные, если банк их отдаёт: `creditLimit` (сколько
доступно по кредиту), `maskedNumber` (уже замаскированный банком), `isHidden`.

### 5. История операций

- `read.transactions` — операции по счёту за период, с пагинацией, если банк
  её поддерживает.
- Операции сверены с приложением банка: суммы, статусы, даты.
- Холды и отменённые операции видны и не считаются списанием.
- Две страницы подряд не дублируют и не теряют операции.

Обязательные поля операции:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | string | Стабильный id для дедупликации. |
| `accountId` | string | `id` счёта из `read.accounts`. |
| `postedAt` | ISO-8601 | Дата и время. |
| `amount` | `{ minor, currency }` | Сумма. |
| `direction` | `in` / `out` / `neutral` | Приход, расход или нейтральная операция. |
| `description` | string | Описание банка как есть. |

Необязательные: `merchant`, `mcc`, `rawCategory`, `logoUrl`, `bankStatus`,
`cashback` (`{ amount, unit }`, где `unit` — `rub`, `points` или `miles`).

Если сумма приходит со знаком, `direction` считается выражением:
`if(lt($.amount,0),'out','in')`.

### 6. Ошибки

- `errors` покрывает хотя бы `401`, `403`, `429`, `5xx` и собственные коды
  банка, которые вы видели.
- «Сессия истекла» отличается от «неверный код» и от «технические работы».

### 7. Гигиена

- `hosts` — полный список хостов, к которым обращается спецификация.
- В спецификации и `bank.md` нет токенов, cookie, реальных номеров счетов, PAN,
  ФИО, телефонов и адресов.
- Спецификация проходит валидацию движка (её запускает сопровождающий при
  ревью).

## P1: если банк умеет

### Карты

`read.cards` + `capabilities: ["cards"]`. Обязательные поля:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | string | Стабильный id карты. |
| `name` | string | Название продукта. |
| `maskedPan` | string | Маскированный номер или последние 4 цифры. |
| `status` | `active` / `blocked` / `expired` / `unknown` | Статус. |
| `currency` | ISO-4217 | Валюта карты. |

Необязательные: `accountId` (привязка к счёту), `expiry`, `art` (обложка:
`{ "url": … }` или `{ "designId": … }`), `balance` (если банк показывает
деньги только на карте).

Обложка:

- есть ссылка на картинку — `art: image($.imageUrl)` или
  `obj('url', $.imageUrl)`;
- есть код дизайна и CDN — `art: obj('designId', $.designId)`;
- нет ни того, ни другого — `art` не заполняется, в `bank.md` пишется, что банк
  не отдаёт обложку. Выдумывать нельзя.

Если банк вообще не отдаёт ни номера, ни last4, напишите в issue: подставлять
выдуманные данные нельзя.

### Пагинация истории

Если банк листает историю курсором или offset, `cursor` обязателен. Если окно
истории ограничено (например, 90 дней), это фиксируется в `bank.md`.

### Прочие данные, которые банк отдаёт

Кредитный лимит, доступный остаток, статус счёта, срок действия карты,
платёжная система, MCC, логотип мерчанта — добавляйте, если они есть в ответе.
Это не обязательно, но повышает качество.

## P2: необязательно

### Кэшбэк

`capabilities: ["cashback"]` + `cashback.programs` — программы и категории.
`capabilities: ["cashbackSelection"]` + `cashback.select` — выбор категорий.
`capabilities: ["cashbackHistory"]` + `cashback.history` — начислено и ожидается
по месяцам, отдельными строками единиц (`rub`, `miles`, `points`, …).

Минимальные поля программы: `id`, `title`, `unit` (`rub`/`points`/`miles` или
свой код), `unitLabel` (как называет банк), `options` (массив категорий).
Категория: `id`, `name`, `percent`.

Полезные, если банк отдаёт: `basePercent`, `periodFrom`/`periodTo`,
`selectionFrom`/`selectionTo`, `state`, `minSelections`, `maxSelections`,
`exactSelections`, `canDeselect`, `cardExternalIds`/`accountExternalIds`,
`earnedMinor`; у категории — `monthlyCapMinor`, `mcc`, `description`,
`selected`.

Если банк не даёт кэшбэк или вы не разобрали его, просто не добавляйте секцию.
Банк без кэшбэка принимается.

### Переводы

Язык спецификаций **пока не поддерживает переводы**: примитива для них нет, и
`transferBySbp` в `capabilities` объявлять не нужно, потому что движок такие
переводы не исполняет. Если банк умеет переводы по телефону или СБП, опишите
разбор в `bank.md`: эндпоинты, подтверждение, идемпотентность, лимиты. Это
пригодится, когда появится примитив; на приёмку спецификации это не влияет и
обязательным не считается.

### Всё остальное

Платежи и автоплатежи, выписки, лимиты и управление картой, push, кредитный
потенциал, инвестиции, семейный доступ, чат поддержки — вне скоупа. Если
окажется, что без этого нельзя получить P0-данные, напишите в issue.

## Как capabilities влияют на приложение

| Capability | Что появляется в UI |
|---|---|
| `accounts` | Всегда: список продуктов и балансы. |
| `cards` | Раздел карт. |
| `transactions` | История операций. |
| `cashback` | Экран программ кэшбэка. |
| `cashbackSelection` | Возможность выбрать категории. |
| `cashbackHistory` | Начислено/ожидается по месяцам в карточке банка. |
| `transferBySbp` | Зарезервировано; движок переводы не исполняет. |

`capabilities` должны соответствовать тому, что реально описано в секциях
`read`/`cashback`. Если capability объявлена, а данных нет, это ошибка: экран
окажется пустым или чтение упадёт.

## Деньги, даты, валюты

- Деньги **всегда** в минорных единицах: `{ "minor": 12843055, "currency": "RUB" }`
  — это 128 430,55 ₽. Числа с плавающей точкой не используем.
- Строки банка (`"1 234,56"`) — `moneyText(value, currency)`.
- Основные единицы числом — `moneyMajor(value, currency)`.
- Уже минорные — `moneyMinor(value, currency)`.
- `RUR` и `810` нормализуются в `RUB` функцией `currency`.
- Даты — ISO-8601 (`2026-11-23T10:15:00.000Z`). Epoch и `{ milliseconds }` —
  `dateAny`/`epochMs`.

## Что подтверждать в `bank.md`

Для каждого пункта P0/P1 — доказательство: дата, версия приложения банка,
метод и путь, обезличенный пример запроса или ответа, чем сверено с приложением
банка. Формат чек-листа — [`checklist.md`](checklist.md).
